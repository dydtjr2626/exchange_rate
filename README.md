# 환율 정보판 (Task 04)

**앱 주소: https://exchange-rate-pi.vercel.app** (심사용 화면: https://exchange-rate-pi.vercel.app/?dev=1)

- 정적 파일: `public/` · 서버리스 함수: `api/chat.js` (Gemini 프록시), `api/rates.js` (한국은행 ECOS 프록시)
- 환율 원천: **한국은행 ECOS Open API** — 통계표 `731Y001` (주요국 통화의 대원화환율, 일별 매매기준율)
  - 원/미국달러 `0000001` (1964-05-04~), 원/일본엔(100엔) `0000002` (1977-04-01~)
- AI 해설(`api/chat.js`): Gemini 스트리밍 응답. 현재 값 + 보고 있는 기간(또는 그래프에서 드래그로 고른 구간)의 요약 통계를 함께 전달하고,
  대화 기억(최근 3번), 한국은행 데이터 직접 조회(함수 호출), 한 줄 해설 자동 생성을 지원합니다.
  "왜 올랐어?" 같은 질문에는 AI가 `get_market_indicators` 도구로 한국은행의 코스피(`802Y001`), 기준금리(`722Y001`), 국고채 3년(`817Y002`), 한·미 정책금리(`902Y006`, 월별)를 조회해
  환율과 "함께 움직인" 지표를 숫자로 설명합니다(원인으로 단정하지 않음). 뉴스는 사용하지 않습니다.
  모델은 `GEMINI_MODELS`(쉼표 구분, 기본 `gemini-flash-lite-latest,gemini-3.5-flash-lite,gemini-3.1-flash-lite`)를 앞에서부터 시도하고 실패하면 다음 모델로 넘어갑니다.
- "오늘의 한 줄 요약"은 AI 가 아니라 코드가 수치와 문장을 모두 만듭니다(AI 가 쓰면 "최근 30일 기준"과 "전일 대비"가 섞이고 표현이 과장되는 문제가 확인됨).
  표현 기준: 하루 변화 ±0.1% 미만 "거의 변동 없음", ±0.5% 미만 "소폭", ±1% 미만 "다소", 그 이상 "큰 폭" (30일 변화는 ±0.5%, ±2%, ±4%).
- 일별 기록 표는 페이지 단위(25/50/100/200건)로 넘기며, 범위를 "표시 기간/전체 기록"으로 바꾸고 날짜로 바로 이동할 수 있습니다.
- 화면 기능: 환율 계산기(원·달러·엔·추가 통화 양방향), 카드의 복사/공유(출처·시각 포함 한 줄), 기간 통계(최고·최저·평균·변동폭),
  교차 환율(달러/엔), 추가 통화(유로·위안 등 9종 중 최대 6개), 다크 모드, 오프라인 안내, 표의 ✨ AI 설명 버튼.
  AI 요청은 서버에서 IP당 분당 20회·하루 300회로 제한합니다(서버리스는 인스턴스마다 메모리가 따로라 최선의 방어입니다).
- 인증키는 서버 환경변수에만 저장합니다 (코드/Git/브라우저 응답에 없음)
  - `GEMINI_API_KEY` : AI 해설
  - `ECOS_API_KEY` : 한국은행 환율 (ECOS Open API 사이트에서 인증키 신청)
- 로컬 실행(`node server.js`)은 프로젝트 밖의 `~/.exchange_rate.env` 파일에서 두 키를 읽습니다.
  ```
  GEMINI_API_KEY=...
  ECOS_API_KEY=...
  ```
  (`ECOS_API_KEY=sample` 은 한국은행의 시험용 키로 요청당 10건만 오므로 동작 확인용입니다.)

## 실행
```
npm i -g vercel
vercel dev          # 로컬 (GEMINI_API_KEY 는 .env.local 또는 vercel env)
vercel --prod       # 배포
vercel env add GEMINI_API_KEY
vercel env add ECOS_API_KEY
```

## 짧은 확인 방법

**① 어디로 가나요**
https://exchange-rate-pi.vercel.app/?dev=1 (로그인 없이 새 시크릿 창에서 열립니다)

**② 3단계 이내로 무엇을 하나요**
1. **실제 환율 조회** 버튼을 누릅니다.
2. **실패 재생** 상자에서 다섯 가지(느린 응답, 401/403, 429, 오프라인, 응답 형식 변경)를 하나씩 골라 **실패 재생**을 누릅니다.
3. 실패 화면의 **↻ 다시 시도**를 누릅니다 (공개 asset `T04-RECOVER-D2` 재생).

**③ 무엇이 보이면 통과인가요**
1. 값(원), 단위(1 USD당 원화 / 100 JPY당 원화), 출처(한국은행 ECOS), 출처 시각, 조회 시각, 기준 시간대(KST)가 보이고, **원자료**의 값과 화면 값이 같습니다. 같은 날 여러 번 눌러도 실제 기록은 1건입니다.
2. 실패마다 다른 `error_code`(`TIMEOUT`, `HTTP_401_403`, `HTTP_429`, `OFFLINE`, `SCHEMA_MISMATCH`)와 안내가 보이고, 마지막 정상값이 남은 채 **오래된 값** 표시가 붙습니다.
3. 상태가 `FRESH`, `error_code: none`으로 돌아오고 다음 날짜 기록이 정확히 1건 추가되며, SHA-256 일치 표시가 보입니다.

**④ 안 될 때는 무엇이 보이나요**
- 서버에 인증키가 없으면: `error_code: NOT_CONFIGURED`와 "서버에 한국은행 인증키가 설정되지 않았습니다." 문구가 보입니다.
- 한국은행이 응답하지 않으면: 실제 실패 상태(`error_code`)와 **↻ 다시 시도**가 보이고, 마지막 정상값에 **오래된 값** 표시가 붙습니다.
- 이른 아침(매매기준율 산출 전)에는 출처 시각이 직전 영업일로 보입니다. 오류가 아닙니다.

비밀값 확인: 브라우저 개발자 도구의 네트워크 탭에는 같은 사이트의 `/api/rates` 요청만 있고, 응답과 코드에 인증키가 없습니다. 내보내기(JSON/CSV)한 기록에는 출처 URL이 `{인증키}`로 가려져 저장됩니다.

## 개발자/심사용 화면 (`?dev=1`)
평소 화면에는 일반 사용자에게 필요 없는 항목을 숨겼습니다. 주소 끝에 `?dev=1`을 붙이면 아래 항목이 보입니다.
(예: `http://localhost:3000/?dev=1`)

- 실패 합성 재생 패널 (5종 선택, `T04-RECOVER-D2` asset 링크, SHA-256 및 기준 해시 검증)
- 원자료(raw response)
- 합성 기록 제거 / 전체 초기화 버튼, 기록 현황 안내
- 복구 결과의 해시 검증 문구, `T04-RECOVER-D2` 안내

> 위 "확인법" 2~4번(실패 재생, 복구, 해시 확인)은 `?dev=1` 화면에서 진행합니다.
